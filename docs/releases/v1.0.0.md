# Version 1.0.0

The first release of Program Delivery Agent demonstrates how a read-only agent can help a technical program manager compare delivery dates and inspect the evidence behind a finding.

[Open the live demo](https://reginankenchor.github.io/program-delivery-agent/)

## What shipped

- A GitHub Actions workflow that runs Qwen3 1.7B across three sample projects.
- A read-only tool that retrieves mapped Jira task and GitHub milestone records stored in the repository.
- Python checks that compare the dates and validate the report’s citations.
- A web workspace for reviewing saved findings, source records, and execution traces.

## Sample scenarios

The demo uses three fictional delivery projects identified by RFP-style tracking IDs (`RFP-001` through `RFP-003`). Each project links one sample Jira task to one sample GitHub milestone so the agent can compare their delivery dates.

| Project | Result |
| --- | --- |
| RFP-001 · CSV Export Delivery | Dates differ. The Jira task is due November 30, 2026, and the GitHub milestone is due December 15, 2026. Review whether they represent the same delivery commitment. |
| RFP-002 · Documentation Preview | Both records show December 3, 2026. The dates match. |
| RFP-003 · Metrics Endpoint | Jira shows December 10, 2026. The GitHub milestone has no due date, so there is insufficient information to compare them. |

## Scope

Version 1 uses fictional Jira and GitHub records. Visitors can inspect the saved run on the website. Agent execution takes place in GitHub Actions. Python checks the source citations and date comparisons, and a person reviews the model’s written explanation and suggested action.
